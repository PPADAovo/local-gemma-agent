# 완료 결과 후 불필요한 반복 방지 요구사항

## 목표

요청한 결과물이 이미 만들어졌거나 외부 작업이 성공한 뒤에는, 체크리스트·검증·결과물 등록 문제로 같은 부작용 작업을 반복하지 않고 실제 결과를 근거로 종료한다.

## 요구사항

1. 성공한 도구 결과는 도구 종류에 맞는 증거를 보존한다. 파일 생성은 실제 파일 경로와 도구가 제공하는 크기·길이·영수증을 기록하고, 사용자에게 결과 파일을 반환한다.
2. 한 번의 도구 호출로 완성되는 작업은 계획에서 UI 시작·대기·종료 같은 허위 하위 단계를 만들지 않는다. 한 결과가 여러 계획 단계를 만족하면 각 단계를 실제 도구 결과로 확인해 처리하되, 근거 없는 단계는 완료 처리하지 않는다.
3. 성공한 비멱등 작업은 완료 검증이 실패하거나 모델이 같은 행동을 다시 제안해도 자동으로 재실행하지 않는다. 같은 브라우저 페이지의 `browser_capture`도 반복 저장하지 않는다. 도구가 제공하는 상태 조회를 우선하고, 성공 여부가 불명확하면 구체적인 결과를 사용자에게 알린다. 실제 성공 실행이나 검증된 관찰 증거가 없는 외부 작업을 완료로 반환하지 않는다.
4. 파일 생성 후 필수 읽기 검증은 유지하되, 이미 저장된 파일이 없는 것처럼 판단해 다시 만들게 해서는 안 된다.
5. 화면 녹화 요청은 요청한 시간을 한 번에 녹화한다. 바탕화면 저장은 Windows의 실제 사용자 바탕화면 경로를 확인하고, 그 목적 폴더를 만든 뒤 저장한다. 임의 절대 경로 허용으로 기존 작업공간 경계를 우회하지 않는다.
6. 완료 답변은 관찰한 도구 결과만 근거로 한다. 요청하지 않은 재생·화면 조작·재발송·재생성은 하지 않는다.
7. 화면 캡처 분기를 포함해 모든 도구 결과 뒤에 최신 체크리스트를 모델에 전달한다. 저장된 캡처 경로가 증거로 뒷받침하는 파일 저장·존재 단계는 완료 처리한다.
8. 같은 작업 루프에서 동일한 PowerShell 명령이나 서비스 검색을 성공 뒤 반복하지 않는다. 동일한 잘못된 도구 인자를 다시 제안하면 도구를 호출하지 않고 명시적인 오류와 함께 중단한다.
9. 스크린샷 이메일은 스킬 이름과 서비스 도구 이름을 구분한다. 저장된 캡처를 먼저 확보한 뒤 실제 Gmail 도구를 검색한다. 화면 조작/검사가 차단되어도 이미지와 저장 경로가 있으면 캡처 첨부에 사용할 수 있으며, 저장을 확인하지 못하면 검색·발송을 중단한다.

## 확인된 문제 경로

- `agent-loop.mjs`의 `directRecording`은 좁은 문장 형식만 빠른 경로로 보내며, 일반 실행의 `todo` 완료 게이트는 `record_screen` 성공을 완료 근거 도구 목록에서 제외한다.
- 일반 실행의 `record()`는 녹화 결과 객체를 관찰 증거로 저장하지만, `files` 결과물 목록에는 `record_screen`을 등록하지 않는다. 저장했다고 답해도 `fileNudged`가 새 파일 생성을 요구할 수 있다.
- 성공한 화면 녹화는 `lastAct`에 포함되어 화면 `look` 재확인을 강제한다.
- `agent.mjs`의 `target()`은 작업공간 상대경로만 허용한다. `record_screen` 출력 폴더는 자동 생성되지 않으며 `recordScreen()`은 목적 폴더 안에서 임시 파일을 만든다.
- `verifyConditions()`는 개별 도구 증거를 받지만, 성공한 부작용과 체크리스트·결과물 등록을 공통으로 조정하지 않는다.
- `browser_capture`는 PNG를 저장하지만 일반 파일 결과 맵에 등록되지 않아 파일 저장 요청 뒤 추가 생성을 유도할 수 있다.
- 같은 페이지의 `browser_capture` 재제안은 현재 브라우저 상태를 기준으로 판별되지 않아 같은 화면을 반복 저장할 수 있다.
- `look`의 화면 전용 처리 경로는 일반 `record()`를 우회하면서 다음 모델 메시지에 체크리스트를 붙이지 않아 완료 단계가 진행되지 않을 수 있다.
- 반복 가드는 `run`과 `plugin_search`를 다루지 않고, 동일한 잘못된 도구 인자도 별도로 제한하지 않아 성공적인 조회와 복구 경로가 반복될 수 있다.
- `plugin_call` 일반 실행에는 첨부 Gmail 전송처럼 동일 인자 재호출을 막는 공통 장치가 없다. 예약 도구에는 별도 중복 판정이 있으므로 이를 보존한다.
- `gmail-attachments` 같은 스킬 이름을 `plugin_call.path`에 넣으면 반복된 도구 인자 오류로 중단될 수 있다. 검색 결과가 없을 때 제한된 Gmail 검색을 수행하지 않고, 스크린샷 이메일도 저장된 캡처를 얻기 전에 서비스 검색·호출을 시도할 수 있다.
- `computer.ps1`은 제한된 창의 픽셀 캡처를 반환하면서 UI 자동화·조작은 차단할 수 있다. `agent-loop.mjs`가 `blocked`만 보고 전체 캡처를 실패로 처리하면, `agent.mjs`가 이미 저장한 이미지 파일을 이메일에 첨부할 기회를 잃는다.

## 범위 밖

- 작업 자체가 실패했거나 실제 요청 조건을 만족하지 못한 경우의 정당한 재시도.
- 검증 후 실제로 필요한 추가 결과물이나 별도 사용자 요청.
- 전체 도구 실행기의 리팩터링 및 비관련 기존 테스트 실패 수정.

## 검증 원칙

- 테스트는 실제 화면 녹화·이메일 발송·외부 서비스 호출 없이 실행 결과를 주입한다.
- 성공한 부작용 호출 횟수, 실제 경로, 크기·길이 증거, 완료 상태를 직접 검증한다.
- Gmail 테스트는 스킬 이름에서 서비스 검색으로 전환하고, 캡처 실패 시 서비스 검색·발송을 하지 않는지 확인한다.
- UI 검사가 차단됐더라도 실제 이미지와 저장 경로가 함께 있으면 스크린샷 첨부만 허용하고, 이미지나 경로가 없으면 발송하지 않는다.
- 확인할 수 없는 영상 재생 가능성·외부 전달 성공은 참으로 가정하지 않는다.
