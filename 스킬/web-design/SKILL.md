# 웹 화면 디자인 기준

코드를 쓰기 전에 아래 4줄을 먼저 정한다. 묻지 않고 정한다. plan의 단계로 넣지 말고, CSS 맨 위 주석에 4줄을 적고 색은 `:root` 변수로 선언한 뒤 바로 화면을 만든다. 마지막 보고에 가정한 것을 한 줄로 알린다.
- 주제·보는 사람·이 화면이 할 일 한 가지
- 색: 이름 붙인 hex 4~6개(바탕, 글자, 강조 1개, 보조)
- 글꼴: 1~2종과 역할(제목/본문). 한글은 "Pretendard","Malgun Gothic",sans-serif 순서
- 배치: 한 문장 설명 + 왼쪽 정렬인지 가운데 정렬인지

만드는 법:
- 첫 화면에는 그 주제에서 가장 특징적인 것 하나를 크게 둔다. 눈에 띄는 요소는 한 곳에만 쓰고 나머지는 조용하게 둔다.
- 글자 크기 단계를 정해 그 안에서만 쓴다(예: 14/16/20/28/40px). 본문 16px 이상, 한 줄 40자 안팎(한글).
- 번호(01·02·03)는 내용이 실제 순서일 때만 붙인다.
- 움직임은 사용자의 조작에 반응할 때만 넣는다. 구역마다 떠오르는 등장 효과는 넣지 않는다.
- 버튼 글자는 누르면 일어나는 일을 쓴다("저장하기"). 오류 문구는 무엇이 잘못됐고 어떻게 고치는지 쓴다.
- 휴대폰 폭(360px)에서 가로로 넘치지 않게 하고, 키보드 포커스 표시를 남긴다.

피할 것(어느 주제에나 나오는 기본값):
- 똑같은 둥근 카드와 같은 회색 그림자의 반복, 장식용 그라데이션
- 크림색 바탕 + 세리프 제목 + 주황 강조, 검정 바탕 + 형광 강조 하나
- 제목 위의 작은 대문자 꼬리표, 제목 속 한 단어만 색 바꾸기, 버튼 끝의 "→"
사용자가 위 모양을 직접 요청했으면 요청을 따른다.

확인: web-preview 스킬로 실제 화면을 열어 처음 정한 4줄과 맞는지 보고, 장식 하나를 빼도 되는지 본다.
파일 구조와 저장 위치는 sites 스킬, 차트는 visualize 스킬을 따른다.
