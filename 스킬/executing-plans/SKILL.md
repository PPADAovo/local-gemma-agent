# 계획 실행

시작:
1. read path=`계획\<작업이름>.md`. 못 읽으면 list path=계획 으로 파일 이름을 확인해 다시 읽는다. 폴더에 계획 파일이 하나도 없을 때만 writing-plans 스킬을 한 번 쓴다.
2. plan에 단계가 아직 없으면 계획의 단계를 그대로 등록한다.

단계마다 반복:
- 고칠 파일을 read로 읽는다 → edit(일부) 또는 write(새 파일)로 고친다.
- 그 단계의 "확인"을 run이나 read로 실제 실행한다.
- 통과한 출력을 본 뒤에만 check 한다. 진행 상태는 plan과 check로만 관리하고, 계획 파일은 다시 고치지 않는다.

실패했을 때:
- 한 단계가 2번 실패하면 skill text=systematic-debugging 을 읽고 원인을 찾아 고친다. 고쳐지면 plan의 남은 단계로 돌아온다.
- 그 단계가 모두 합쳐 3번 실패하면 멈추고 보고한다: 실패한 단계, 실행한 명령, 오류 출력, 시도한 것.
- 계획이 실제 코드와 맞지 않으면 plan을 고쳐 등록하고(바꾼 이유 한 줄) 이어서 한다. 완료 기준은 낮추지 않는다.

멈추고 묻는 경우: `(확인 필요)` 가 붙은 단계 앞에서만 reply(needsInput=true)로 묻는다. 그 외에는 계속할지 묻지 않는다.

끝내기:
- 마지막 단계 뒤에 계획의 "완료 기준" 명령을 run으로 한 번 실행한다. 단계별 확인을 처음부터 다시 돌리지 않는다.
- 보고: 바꾼 파일 / "확인: <명령> → <핵심 출력 한 줄>" / 남은 것. 실행하지 못한 확인은 "미확인: <이유>".
- 다 못 끝내면 note text="계획 <이름>: 끝낸 단계 / 남은 단계" 를 남긴다.
