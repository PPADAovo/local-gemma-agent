# Premiere 편집 경로

`discover_tools` 결과에서 실행 파일을 확인합니다. 이 PC에서 2026-11-19 확인한 버전은 Premiere Pro 2020이지만 매 작업의 실제 발견 결과를 우선합니다. 최신 UXP는 Premiere 25.6 이상을 요구하므로 2020에서 UXP 코드 생성만 하고 실행됐다고 보고하지 않습니다.

CEP 브리지가 발견되지 않으면 화면 조작 경로로 진행합니다. Premiere에는 Photoshop처럼 File > Scripts > Browse가 있다고 가정하지 마세요. 로컬 UI에서 가져오기·시퀀스 생성·편집·저장이 가능한지 확인하기 전에 외부 AI로 넘기지 않습니다.

## 컷 편집

- windows에서 프로젝트 이름이 맞는 창을 선택하고 focus/look으로 타임라인과 활성 시퀀스를 봅니다. 프로젝트 패널의 클립과 타임라인 클립을 구별하세요.
- 프로젝트 패널에서 클립을 끌어올 때는 최신 look에서 확인한 실제 클립 행·썸네일을 시작점으로 선택합니다. `drag` 스키마에 `from`/`to`가 있으면 소스 E번호와 대상 타임라인 E번호를 우선 연결하고, 타임라인 요소가 없을 때만 끝점에 이미지 좌표를 씁니다. 패널의 빈 여백이나 선택 표시와 무관한 위치를 소스로 추정하지 마세요. 드래그 후에는 타임라인에 실제 비디오·오디오 항목이 생겼는지 새 화면으로 확인합니다.
- 원본 사본으로 저장해야 하는 작업이면 먼저 메뉴에서 Save As를 찾아 새 PRPROJ 경로를 지정합니다. 원래 프로젝트를 닫거나 다른 미저장 문서를 버리지 않습니다.
- 컷 지점은 사용자가 지정한 타임코드/발화/구간을 기준으로 정합니다. 타임코드가 없으면 프레임 단위 정확도를 확인할 근거(재생·파형·사용자 지정 대본)가 필요합니다. 화면 픽셀만 보고 초 단위 길이를 추정하지 않습니다.
- 편집할 트랙의 잠금·대상 지정과 연결된 비디오/오디오 선택 상태를 확인합니다. 다른 트랙이 잠겼는지/선택됐는지에 따라 Ripple Delete가 다른 클립을 움직일 수 있습니다.
- 키보드 단축키가 사용자 설정인지 모르면 메뉴의 명령명·단축키를 먼저 봅니다. 이전 버전 또는 다른 앱의 기본 키를 추측하지 않습니다.
- 클립 이동·트리밍은 타임라인을 충분히 확대하고 현재 선택·스냅 상태를 본 뒤 한 번 수행합니다. 조작 뒤 새 look으로 시작·끝·빈 구간·겹침과 파형을 다시 확인합니다.
- 속도, 게인, 페이드, 효과는 요청에 포함된 경우에만 변경합니다. '컷과 연결만'이면 추가하지 않습니다.

## 완료 증거

PRPROJ가 저장됐다는 사실만으로 컷 정확도를 증명하지 않습니다. 시퀀스 시작/끝 길이, 편집한 각 연결부의 영상·음성, 트랙 구조를 확인합니다. 재생 또는 청취가 가능한 도구가 없으면 해당 검증은 아직 못 했다고 기록하세요. 내보내기를 요청했다면 내보내기 설정과 생성된 영상의 실제 해상도·프레임레이트·길이 및 재생 결과까지 확인합니다. 렌더 파일을 PRPROJ 대신 전달하지 않습니다.

PRPROJ 내부 XML을 읽어 보조 검증할 때는 시퀀스가 참조하는 실제 트랙 아이템과 소스 In/Out을 연결해야 합니다. 같은 숫자를 가진 프로젝트 패널의 원본 클립을 타임라인 결과로 잘못 세지 마세요. XML 구조를 모르면 구조 분석 결과만 보고하고 검증 성공으로 바꾸지 않습니다.
