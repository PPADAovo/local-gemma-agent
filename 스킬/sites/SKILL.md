# 웹사이트 만들기

이 PC의 `작업공간\사이트\<이름>\` 폴더에 만든다. 사용자가 공개·배포·올리기를 요청하면 다 만든 뒤 아래 "인터넷에 공개" 순서를 따른다.

순서:
1. 목적, 보는 사람, 들어갈 내용(문구·연락처·사진)을 확인한다. 모르면 한 번만 묻는다. 사용자가 주지 않은 연락처·가격·후기는 지어내지 않고 `<전화번호>` 처럼 비워 둔다.
2. 폴더 이름을 정한다(영문 소문자·하이픈). list path=사이트 로 같은 이름이 있는지 확인한다.
3. 파일을 쓴다.
   - write path=사이트\<이름>\index.html
   - write path=사이트\<이름>\style.css
   - 동작이 필요할 때만 write path=사이트\<이름>\script.js
   - 쪽이 여러 개면 about.html 처럼 같은 폴더에 두고 상단 메뉴로 서로 연결한다.
4. open_file path=사이트\<이름>\index.html 로 연다.
5. web-preview 스킬대로 실제 화면을 확인한다: 제목이 보이는지, 메뉴 링크가 열리는지, 창을 좁혀도 깨지지 않는지.

만드는 법:
- `<meta name="viewport" content="width=device-width,initial-scale=1">` 를 넣고 휴대폰 폭(360px)에서 가로로 넘치지 않게 한다.
- 글꼴은 `"Malgun Gothic",sans-serif`, 본문 16px 이상, 글자와 배경의 명암을 충분히 준다.
- 사진이 없으면 색 면이나 CSS 도형으로 대신한다. 인터넷의 남의 사진 주소를 넣지 않는다.
- 외부 라이브러리 없이 HTML·CSS·JavaScript만 쓴다.
- 문의 양식은 실제로 전송되지 않는다. 메일 링크(`mailto:`)로 대신하고 그렇게 알린다.

기존 사이트를 바탕으로 새로 만들기: run text=`Copy-Item -LiteralPath '사이트\<원본>' -Destination '사이트\<새이름>' -Recurse` 로 복사한 뒤 새 폴더만 고친다. 원본은 건드리지 않는다.
인터넷에 공개(배포) — 사용자가 요청했을 때만:
1. 위 5번까지 끝내고, 폴더 맨 위에 index.html이 있는지 확인한다. 연락처 자리표시(`<전화번호>` 등)가 남아 있으면 공개 전에 알린다.
2. deploy_site path=사이트\<이름> text=<이름> 을 한 번 부른다. 앱이 공개 승인 카드를 띄우고, 저장소(<깃허브아이디>.github.io)가 없으면 사용자에게 한 번 만들어 달라고 요청한다.
3. 결과의 주소를 그대로 알린다. "아직 주소에서 확인하지 못했습니다"면 몇 분 뒤 열린다고 알리고 같은 배포를 반복하지 않는다.
4. 고친 뒤 다시 올릴 때도 같은 이름으로 deploy_site를 부른다(같은 주소가 새 내용으로 바뀜).
소스 코드를 GitHub 저장소로 공유하는 일(사이트 공개가 아님)은 share 스킬을 따른다.
