# 완료 전 검증

이번 대화에서 직접 실행한 결과가 없으면 완료라고 말하지 않는다. "될 것이다", 이전에 본 결과, 코드만 읽고 내린 판단은 증거가 아니다.

순서:
1. 무엇이 증거인지 정한다.
   - 테스트 통과 → 테스트 명령의 출력(실패 0건)
   - 빌드 성공 → 빌드 명령의 종료 코드 0
   - 버그 수정 → 실패하던 입력을 다시 실행한 출력
   - 화면 변경 → web-preview 스킬로 본 실제 화면
   - 파일 생성 → read 또는 list 결과
2. 그 명령을 지금 run으로 전부 실행한다(일부만 돌리지 않는다).
3. 출력을 끝까지 읽는다: 종료 코드, 실패 건수, 경고.
4. 결과대로 보고한다.
   - 통과: "확인: <명령> → <핵심 출력 한 줄>"
   - 실패: 실패한 항목과 출력을 그대로 적고 이어서 고친다.
   - 실행하지 못함: "미확인: <이유>"라고 적는다.

보고 형식: 바꾼 파일 / 실행한 명령과 결과 / 남은 것.
"아마", "~일 것 같습니다"로 끝나는 완료 보고는 쓰지 않는다.
계획 실행(executing-plans)에서 완료 기준 명령을 방금 실행했으면 같은 명령을 다시 돌리지 않고 그 출력으로 보고한다.
