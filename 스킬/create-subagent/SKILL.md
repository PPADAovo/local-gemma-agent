# 전용 에이전트 만들기

에이전트 하나는 `에이전트\<이름>.json` 파일 하나다. 메시지를 `@이름 요청` 으로 시작하면 그 에이전트가 처리한다.

순서:
1. 이름, 맡길 일, 화면 조작이 필요한지 모르면 reply(needsInput=true)로 한 번에 묻는다.
2. list path=`<스킬폴더>\..\..\에이전트` 로 같은 이름이 있는지 확인한다.
3. write path=`<스킬폴더>\..\..\에이전트\<이름>.json` text=아래 JSON.
4. read로 다시 읽어 JSON이 맞는지 확인하고, 부르는 법(`@이름 요청`)을 알린다.

```
{
  "name": "<이름>",
  "description": "<한 줄 설명>",
  "model": "",
  "tools": ["reply","list","read","write","edit","run","web_search","web_read","note","recall","skill","wait"],
  "instructions": "<이 에이전트만의 지침. 무엇을 하고, 끝났는지 어떻게 확인하는지>",
  "memory": true
}
```

- model을 비우면 기본 모델을 쓴다. 설치되지 않은 모델 이름을 넣으면 실행되지 않는다.
- tools를 빈 배열로 두면 모든 도구를 쓴다. 조사용은 web_search·web_read, 코딩용은 write·edit·run, 화면 조작용은 look·click·type·key 를 넣는다.
- memory가 true면 `기억\에이전트\<이름>.md` 에 따로 기억한다.

instructions 쓰는 법 (이 문장이 그 에이전트의 전부다):
- 첫 문장에 역할을 쓴다: "너는 <무엇>만 하는 에이전트다."
- 받는 것과 돌려줄 것을 쓴다: 어떤 요청을 받고, 결과를 어떤 형식으로 보고하는지.
- 끝났는지 확인하는 방법을 쓴다(예: "run으로 테스트를 실행해 통과를 본 뒤 보고한다").
- 하지 않을 일을 한 줄 쓴다(예: "파일을 고치지 않는다", "화면을 조작하지 않는다").
- 3~6문장으로 쓴다. 모든 에이전트에 공통인 규칙(안전, 말투)은 지침.md에 있으므로 다시 쓰지 않는다.

확인: 만든 뒤 사용자에게 `@<이름> <짧은 시험 요청>` 을 한 번 보내 보라고 알린다. tools에 delete나 run을 넣었으면 그 사실을 알린다.
