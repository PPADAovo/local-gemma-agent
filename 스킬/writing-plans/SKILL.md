# 코딩 계획 쓰기

계획은 프로젝트 폴더의 `계획\<작업이름>.md` 파일 하나다. 묻지 않고 쓴다.
묻는 경우는 하나뿐이다: 요청만으로는 고칠 프로젝트 폴더나 대상 파일을 정할 수 없을 때 reply(needsInput=true)로 한 번 묻는다. 나머지는 가정을 계획 파일에 적고 진행한다.

순서:
1. list와 read로 관련 파일을 먼저 읽는다. 읽지 않은 파일은 계획에 넣지 않는다.
2. 빌드·테스트 명령을 찾는다(package.json의 scripts, 빌드하기.cmd, tests 폴더). 없으면 "실행해서 확인할 명령"을 직접 정한다.
3. write path=`계획\<작업이름>.md` 로 아래 형식을 저장한다.
4. plan 도구에 같은 단계를 등록한다.
5. skill text=executing-plans 를 한 번 읽고 1단계부터 바로 실행한다. 이 스킬(writing-plans)을 다시 부르지 않는다.

형식:
```
# <작업 이름>
목표: <한 문장>
가정: <묻지 않고 정한 것. 없으면 "없음">
완료 기준: <실행하면 통과가 보이는 명령과 기대 출력>

## 단계
1. <파일 경로>: <무엇을 바꾸는지> / 확인: <명령 또는 read로 볼 내용>
2. ...
```

규칙:
- 한 단계는 파일 1~2개 크기로 쪼갠다. 3~8단계.
- 단계마다 실제 파일 경로와 확인 방법을 적는다. "적절히 수정" 같은 말은 쓰지 않는다.
- 요청받지 않은 기능, 리팩터링은 넣지 않는다.
- 아래 일이 들어가는 단계는 끝에 `(확인 필요)` 를 붙인다: 파일·폴더 삭제, git push, 배포, 프로그램 전역 설치, 환경 변수·레지스트리 변경, 실행 중인 프로세스 강제 종료, .env·토큰·키 파일 수정, 메시지·메일 보내기, 결제.

여러 대화에 걸친 큰 목표는 goal 스킬을 쓴다.
