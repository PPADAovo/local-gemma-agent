# 코드 검토

읽기만 한다. 고쳐 달라고 하지 않았으면 파일을 바꾸지 않는다.
모든 run 앞에 `Set-Location -LiteralPath '<프로젝트 폴더>';` 를 붙인다.

순서:
1. 범위: run text=`git status --short; git diff --stat` 로 바뀐 파일을 본다. git 저장소가 아니면 사용자가 말한 파일을 list로 확인한다.
2. 변경 읽기: run text=`git diff -- '<파일>'` 로 바뀐 줄을 보고, 새 파일은 read로 전체를 읽는다.
3. 따라가기: 바뀐 함수 이름을 run text=`git grep -n "<함수이름>"` 으로 찾아, 그 함수를 부르는 곳과 관련 테스트를 read로 읽는다.
4. 실패하는 입력 찾기: 빈 값, 없는 파일, 0, 아주 긴 값, 한글 경로, 같은 동작 두 번 실행 중 실제로 깨지는 경우를 찾는다.
5. 테스트: 프로젝트에 테스트 명령이 있으면 run으로 실행해 결과를 적는다. 바뀐 동작을 확인하는 테스트가 없으면 "테스트 누락"으로 적는다.

발견마다 적는 것:
- 파일과 줄 번호
- 어떤 입력·상황에서 무슨 일이 생기는지
- 심각도: 높음(데이터 손실·실행 불가) / 중간(일부 기능 오동작) / 낮음(가독성·사소한 문제)
- 고치는 방법 한 줄

규칙:
- 실제로 읽은 코드에서 확인한 것만 적는다. 추측은 "미확인"으로 따로 적는다.
- 심각도 높은 것부터 적고, 취향 문제(이름, 줄바꿈)는 최대 3개까지만 적는다.
- 실행하지 못한 검사는 못 했다고 적는다. 문제가 없으면 무엇을 확인했는지와 함께 없다고 말한다.

보안 위주 점검은 review-security 스킬을 쓴다.
