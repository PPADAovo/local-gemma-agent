# 보안 점검

읽기만 한다. 고쳐 달라고 하지 않았으면 파일을 바꾸지 않는다.

순서:
1. 범위 확인: git 저장소면 run text=`git status --short; git diff --stat` 로 바뀐 파일을 본다. 아니면 list로 프로젝트 파일을 본다.
2. 바뀐 파일을 read로 읽고, 입력이 들어오는 곳(요청, 파일, 명령줄 인자, 환경 변수)부터 그 값이 쓰이는 곳까지 따라간다.
3. 아래 항목을 확인한다.
   - 비밀 정보: 코드·설정·커밋에 토큰, 비밀번호, API 키가 들어 있는가. run text=`git grep -n -I -E "(api[_-]?key|secret|token|password)\s*[:=]"`
   - 명령 실행: 사용자 입력이 셸 명령, eval, exec에 그대로 들어가는가
   - 경로: 사용자 입력으로 파일 경로를 만들 때 `..` 로 폴더 밖을 읽거나 쓸 수 있는가
   - SQL·HTML: 입력을 문자열로 이어 붙여 쿼리나 HTML을 만드는가
   - 인증·권한: 로그인 확인이나 소유자 확인이 빠진 요청이 있는가
   - 의존성: package.json·requirements.txt 가 있으면 run text=`npm audit --omit=dev` 또는 `pip list --outdated` (설치되어 있을 때만)
   - 기록: 로그에 비밀번호·토큰·개인정보를 남기는가
4. 발견마다 적는다: 파일과 줄, 어떤 입력으로 무슨 일이 생기는지, 심각도(높음·중간·낮음), 고치는 방법.

규칙:
- 실제로 읽은 코드에서 확인한 것만 적는다. "있을 수 있다"는 추측은 "미확인"으로 따로 표시한다.
- 실행하지 못한 검사는 못 했다고 적는다.
- 찾은 비밀 값은 답변에 그대로 옮기지 않고 앞 4글자만 보여 준다.
- 문제가 없으면 무엇을 확인했는지와 함께 없다고 말한다.
