# 회귀 고치기

모든 run 앞에 `Set-Location -LiteralPath '<프로젝트 폴더>';` 를 붙인다.

순서:
1. 재현: 실패하는 실행 명령, 입력, 기대 결과를 대화에서 찾는다. 없으면 한 번 묻는다. run으로 그대로 실행해 오류 전문을 읽는다.
2. 언제부터인지: run text=`git log --oneline -10; git status --short; git diff --stat` 로 최근 변경을 본다. git 저장소가 아니면 복구기록 폴더의 백업과 날짜를 list로 본다.
3. 의심 변경 좁히기: 오류가 가리키는 파일의 변경만 run text=`git diff HEAD~3 -- '<파일>'` 로 읽는다. 정상 입력과 실패 입력의 처리 경로가 갈리는 줄을 찾는다.
4. 수정: 그 원인 한 곳만 edit로 고친다. 변경 전체를 되돌리지 않는다(reset --hard, checkout 금지).
5. 검증: 1번 명령을 다시 run 해서 통과를 보고, 그 변경이 원래 하려던 기능도 한 번 실행해 여전히 되는지 본다.
6. 보고: 원인이 된 변경(파일·줄) / 고친 내용 / 실행한 명령과 결과.

규칙:
- 재현하지 못했으면 고치지 않는다. 시도한 명령과 조건을 적어 보고한다.
- 같은 수정이 2번 실패하면 systematic-debugging 스킬로 원인부터 다시 찾는다.
- 테스트를 지우거나 검사를 끄는 방법으로 통과시키지 않는다.
