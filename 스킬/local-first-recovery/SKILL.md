# 로컬 실행과 복구

단순한 조회·한 번의 수정은 바로 해당 도구를 사용합니다. 여러 앱이나 여러 결과물이 필요한 작업은 요청을 관찰 가능한 완료 조건으로 나눕니다. 계획 문장만으로 수행했다고 보고하지 않습니다.

## 다음 행동을 정하는 데 필요한 근거

- **목표:** 사용자 대상 파일·앱·수정 범위·출력 경로. 대화와 파일에 이미 있는 정보를 먼저 읽습니다.
- **현재 상태:** 최신 도구 결과, 현재 선택 창, 활성 문서·패널, 이미 저장되거나 전송된 결과.
- **수단:** 실제 검색한 설치 프로그램·도구와 입력 형식, 적용할 로컬 스킬. 없는 도구명이나 메뉴를 지어내지 않습니다.
- **검증:** 다음 동작이 성공하면 무엇이 달라져야 하는지 정하고, 실행 후 실제 차이를 읽습니다.

화면 조작이 필요하면 computer-use 스킬을, 편집·설계 앱이면 creative-apps 스킬을 읽습니다. 서비스 작업은 plugin_search/service_search로 실제 연결과 입력 형식을 확인합니다. 스킬은 설명서이며 실행 도구 자체가 아닙니다.

## 실패 후 복구

1. 방금 실패한 도구·입력·오류와 부분적으로 수행된 결과를 확인합니다. 전송·저장·삭제가 실행됐는지 불명확하면 먼저 결과를 조회합니다.
2. 입력 형식 오류는 실제 스키마에 맞게 고칩니다. 화면 대상 오류는 창을 다시 찾고 focus/look으로 새 좌표를 얻습니다. 도구 또는 API 지원 오류는 설치된 다른 로컬 경로를 찾습니다.
3. 같은 입력과 같은 결과를 반복하지 않습니다. 이미 전송한 메시지·수행한 결제·작성한 파일을 새 작업처럼 다시 수행하지 않습니다. 다른 방식의 시도는 실패 원인에 근거해야 합니다.
4. 취소·권한 거절·사용자만 가능한 로그인은 모델 능력 부족이 아닙니다. 외부 AI로 우회하지 않습니다. 필요한 입력이나 사용자 행동을 구체적으로 알립니다.
5. 외부 AI는 로컬 실행 실패 또는 지원 불가가 확인된 경우에만 보조자로 사용합니다. 도움 요청에는 원래 목표, 최소한의 실패 증거, 이미 완료된 부분, 필요한 다음 판단을 포함하고 인증 정보는 제외합니다. 전체 대화나 프로젝트를 불필요하게 전송하지 않습니다.
6. 외부 AI의 답변은 조언입니다. 로컬 실행기로 필요한 작업을 수행하고 결과를 검증한 뒤 완료 여부를 판단합니다. 이미 수행한 부작용이 있는 전체 작업을 처음부터 재생하지 않습니다.

## 완료 보고

관찰된 결과·저장 위치·검증 방법을 보고합니다. 확인하지 못한 재생·음질·화면·실제 계정 작업은 별도로 구분합니다. '가능하다', '코드를 만들었다', '도구가 성공을 반환했다', '결과를 다시 열어 확인했다'는 서로 다른 상태입니다.
